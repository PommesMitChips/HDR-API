# HTML frontend offline checks

Run from the HDR_API repository with PowerShell and the .NET 10 SDK:

```powershell
./Tools/HtmlChecks/Check.ps1 -GameBin 'C:/path/to/SpaceEngineers/Bin64'
./OptionalMods/HDRHtmlFrontend/Build.ps1 -GameBin 'C:/path/to/SpaceEngineers/Bin64'
```

`Check.ps1` compiles all frontend sources, the packaged HDR SDK, the consumer helper/example, the current core, and the canonical PB/mod helpers with C#6 against the installed game assemblies. The preserved core-seam host tests use modern .NET test syntax; the independent production compilation enforces C#6. Every suite has its own entry point. The root `Tools/Checks/Program.cs` is never included.

The gate also requires Windows .NET Framework 4.8 for the installed game's actual whitelist analyzers. The ModApi checks invoke the three installed default registration routines and certify allowed code plus rejected unused-reflection and pragma controls before checking the frontend, core, and mod consumer sources. PB helpers and demos additionally require the actual **Ingame** target, the stock PB blacklist, and the installed `TypeSafetyAndBlockRewriter` followed by successful emission. These checks execute no candidate code and add no whitelist permissions or handwritten bypass annotations. The host runs on .NET Framework because loading these defaults on modern .NET merges BCL assembly identities and breaks legitimate duplicate-registration guards. `Whitelist/Check.ps1` discovers the selected SDK compiler dynamically; its standalone parameters permit alternate framework/compiler locations. All dependencies and reports stay under the output directory.

ModApi validation prepends the installed official compatibility import header, extracted from `MyScriptManager.UpdateCompatibility` IL without executing that game method. Receipts retain its assembly, method IL, header and preprocessed-source fingerprints. A compiler ambiguity control must fail while its explicit type-alias counterpart succeeds. Historical compatibility string replacements are recorded as not applied; the commissioned sources use the current API. Ingame validation independently compiles each complete global `Program:MyGridProgram` wrapper: the canonical helper, minimal authored-HTML loader, native-sprite demo, camera/ellipsoid composition demo, and preserved advanced bindings demo. `PbSources.json` records those exact sources, and generated paste bodies preserve the raw demos byte for byte. The PB suite reads the published `PlainHtmlPbDemo.html` directly; the earlier SVG admission fixture reads the preserved advanced demo.

The trigger-bearing positive control must change under the official PB rewriter. Each candidate must undergo that same rewriter and emit successfully; a valid no-op is recorded honestly. The gate matches every candidate's original and rewritten fingerprints and requires its change flag to agree with those hashes.

`Suites.json` records the reviewed counts for eight suites: parser, layout, retained renderer, native LCD, host, core seams, PB adapter, and composition. `Fixtures.json` records accepted fixture paths and SHA256 values. Prior accepted behavior stays covered; commissioned deltas add focused checks rather than replacing the earlier fixtures. Future fixture changes require intentional manifest/count updates after review. Runtime sources are linked from their actual repository locations; staged production snapshots are not compiled. PB paste fragments gain standard imports in generated output files; there are no second checked-in PB SDKs.

Retained checks exercise real compiled HDR geometry and generate HUD/world/grouped SVG previews and CPU measurements. These are offline receipts, not live game, GPU, or visual acceptance. Native and host checks use offline gateway/surface doubles. Reflection belongs only to these test executables, not frontend production sources.

Build logs, generated wrappers, binaries, source hashes, and receipts default to `artifacts/html-prototype/checks-VERSION`, where VERSION comes from the frontend metadata. `-OutputDirectory` selects another location inside the repository's `artifacts` directory; paths outside it are rejected. No NuGet packages or game assemblies are downloaded. The scripts neither install mods nor launch the game, and never modify worlds or Pulsar profiles. Actual whitelist validation retains separate target-specific source hashes in the composite receipt.

The default build always runs the complete gate. After a complete successful check, `Build.ps1 -VerifiedReceipt './artifacts/html-prototype/checks-0.2.0/receipt.json'` can package the already verified state: it requires all current source, docs, tools, eight suite results, four target-specific whitelist results, successful PB engine rewriting/emission, and inspected game/compiler assembly hashes to match. Changed inputs require a fresh gate. There is no unchecked skip flag.

Composition checks exercise source-slot admission, lifecycle, geometry and rendering dispatch offline. Native bridge ABI/service checks belong to the root/native release gates. The HTML gate and package do not establish live capture, HLSL execution, GPU composition, visual quality or player-input acceptance, and do not install a native plugin.

`Build.ps1` produces `artifacts/HDR-HTML-Frontend-VERSION.zip` from the metadata version, preserving earlier versioned packages. Sorted entry paths and fixed timestamps make identical source inputs produce identical ZIP bytes. The ZIP has a game-loadable `Data` directory and metadata, documentation, and examples. It excludes repository build tools, test executables, SDK duplication, imported DLLs, and private receipts. Rebuild it from the source repository, rather than from an extracted mod ZIP. The frontend remains **ALPHA**, implementing **profile 1**; full browser HTML5/JavaScript support is outside this profile.
